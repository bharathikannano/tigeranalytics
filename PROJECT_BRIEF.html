📤 Upload Flow — Step by Step
1
User drops or selects a CSV file → Axios POSTs multipart/form-data with onUploadProgress → live progress bar updates in UI
2
Express: multer checks MIME type + file size → rejects non-CSV (415) or oversized files (413) before any parsing
3
PapaParse parses buffer in-memory → header normalisation (trim → lowercase → underscores) → 5 required columns verified
4
Every row validated via validateCsvRow(row, index) → if any fail, 422 with full row-level error list returned; nothing is written
5
All rows valid → single SQLite transaction: INSERT upload_log + all N pricing_records atomically. Any failure rolls back entirely.
6
201 success → TanStack Query invalidateQueries(['upload-logs']) → upload history auto-refetches → success banner shown
MethodPathDescription
POST/api/pricing/uploadValidate all rows → bulk-insert in one transaction
GET/api/pricingList / filter records — 7 filters + pagination + sort
PUT/api/pricing/:idPartial update — any subset of the 5 pricing fields
GET/api/pricing/upload-logsPaginated upload audit history
GET/healthHealth check { status: "ok", ts: "..." }

Design Decisions

Architectural choices and the reasoning behind each one

D1
Database
SQLite + better-sqlite3

Zero infrastructure overhead. Synchronous API simplifies Express handlers. WAL enables concurrent reads without blocking writes.

D2
Validation
All-or-nothing CSV validation

Every row validated before any write. No partial state in the database. Users receive a complete error list to fix and re-upload.

D3
Performance
In-memory CSV parsing

multer memoryStorage + PapaParse from Buffer — no temp files on disk. Header normalisation (trim → lowercase → underscores) makes the format forgiving.

D4
Integrity
Atomic bulk insert transaction

upload_log + all pricing_records in one SQLite transaction. Any failure rolls everything back — audit log stays in sync.

D5
Security
ORDER BY allowlist

sortBy and sortDir validated against hardcoded arrays before SQL interpolation — prevents ORDER BY injection attacks entirely.

D6
API Client
Axios HTTP client

Clean instance config, interceptors for error standardisation, automatic serialisation, and native onUploadProgress — no XMLHttpRequest boilerplate.

D7
Dev DX
Vite /api proxy

Proxies /api to port 4000 in development. Eliminates dev CORS issues. Production uses the VITE_API_URL environment variable.

D8
Performance
5 covering indexes

On store_id, sku, record_date, (store_id, sku), and product_name — matching the most common filter and sort patterns without full table scans.

D9
API Design
COALESCE partial UPDATE

PUT endpoint only needs changed fields. COALESCE(@value, existing) keeps untouched fields intact — reducing payload and accidental overwrites.

D10
Reliability
Centralised error handler

One middleware handles multer, validation, and 500 errors uniformly. Stack traces are suppressed in NODE_ENV=production.

D11
State Mgmt
TanStack Query

Replaces manual loading/error/data boilerplate. Provides 30s cache, auto-refetch on mutation, and optimistic cache patches for instant inline edits.

D12
UX
filters vs activeFilters split

FilterBar inputs update filters (local state). Search click copies to activeFilters (query key). No network call on every keystroke.

Assumptions

Accepted constraints, trade-offs, and scope boundaries

🔐
Accepted Risk
Internal users only — no auth layer

Trusted retail operations staff only. Adding OAuth2 / JWT would be the first hardening step for external access.

📄
Verified
CSV format contract

Feeds always contain the 5 required columns (Store ID, SKU, Product Name, Price, Date). Header matching is case-insensitive and whitespace-tolerant.

📦
Configurable
Reasonable file sizes

Uploads expected under 50 MB per file. Limit is configurable via the UPLOAD_SIZE_LIMIT_MB environment variable.

🖥️
Scale Limit
Single-server deployment

SQLite suits one process. Horizontal scaling to multiple API servers requires migrating to PostgreSQL with a connection pool.

➕
Design Choice
Append-only ingestion

Uploads always insert new rows. Duplicate records are permitted. De-duplication or upsert logic can be added as a follow-up requirement.

📅
Flexible
Date format flexibility

Any date parseable by new Date() is accepted and normalised to ISO YYYY-MM-DD format before storage.

🚀
Infra Dep
Node.js v18+ runtime

A process manager (pm2 or systemd) is expected in production to handle restarts, log rotation, and process supervision.

🌍
Supported
Multi-country stores

Store ID is a free-form string — no country-specific format enforced. Product names support Unicode, enabling multi-language entries.

WHERE store_id LIKE @storeId
  AND sku LIKE @sku
ORDER BY created_at DESC

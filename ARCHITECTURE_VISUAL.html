📂 Phase 1 — File Selection
1
🧑 → UploadPage
Admin drops CSV onto the drag-and-drop zone, or clicks to browse files
2
UploadPage → UI
Shows file name, size preview, enables the ⬆ Upload button
3
🧑 clicks Upload → UploadPage
Triggers handleUpload(), sets status='uploading', clears previous errors
📡 Phase 2 — Network Transfer (XHR with progress)
4
UploadPage → XHR
Opens XHR POST with file wrapped in FormData (multipart/form-data)
POST /api/pricing/upload
5
XHR → UploadPage (continuous)
upload.progress events fire as bytes are sent → progress bar % updates in real time
🛡 Phase 3 — File Guard (multer)
6
Express → multer fileFilter
Checks MIME type: text/csv, application/vnd.ms-excel, text/plain, or .csv extension
7
multer → size check
Enforces max file size ≤ 50 MB (configurable via UPLOAD_SIZE_LIMIT_MB env var)
❌ Wrong file type → HTTP 415 Unsupported Media Type → error banner shown
multer → errorHandler → { error: "Invalid file type" } → flow ends
❌ File too large → HTTP 413 Payload Too Large → error banner shown
multer LIMIT_FILE_SIZE → errorHandler → { error: "File too large" } → flow ends
📄 Phase 4 — CSV Parsing (PapaParse, in-memory)
8
Route handler → PapaParse
Parses CSV from in-memory Buffer with header:true, skipEmptyLines:true
9
Header normalisation
Headers trimmed, lowercased, spaces → underscores  e.g. "Store ID" → "store_id"
10
Column check
Verifies all 5 required columns: store_id, sku, product_name, price, date
❌ Missing column → HTTP 422 MissingColumns { expected: [...], found: [...] } → flow ends
✅ Phase 5 — Row-Level Validation (all-or-nothing)
11
Route → validateCsvRow() × N rows
Per row: store_id required · sku required · product_name required · price ≥ 0 numeric · date parseable
❌ Any row invalid → HTTP 422 ValidationErrors — NOTHING written to DB
Full row-error array returned e.g. "Row 3: price must be non-negative (got 'free')"
UploadPage renders scrollable list → admin fixes CSV and re-uploads
💾 Phase 6 — Atomic Database Write (SQLite transaction)
12
Route → SQLite transaction BEGIN
Both the audit log insert and all record inserts are wrapped in one atomic transaction
13
INSERT upload_logs
Audit entry created: id, filename, row_count, error_count=0, status='success'
14
INSERT pricing_records × N
Bulk inserts all rows. Dates normalised to YYYY-MM-DD. Prices cast to REAL.
15
COMMIT → HTTP 201 → UploadPage
Returns uploadId, rowsInserted, fileName to client
{ message: "Upload successful", uploadId, rowsInserted: N }
16
UploadPage → UI
✅ Success banner shown · Upload History table refreshes with new log entry

🚀 Phase A — Auto-search on Mount
1
SearchPage useEffect → searchPricing(DEFAULT_FILTERS)
Fires automatically when the page first loads — shows the latest 50 records immediately without any user action
🔍 Phase B — Filtered Search
2
🧑 → FilterBar
Admin fills filter fields: Store ID, SKU, Product Name, Date From/To, Min/Max Price, Sort column/direction
3
🧑 clicks Search → SearchPage
onSearch() fires, loading skeleton shown, previous results cleared
4
SearchPage → api/pricing → Express
Builds URLSearchParams from filter state, fires GET request
GET /api/pricing?storeId=STORE-001&page=1&pageSize=50&sortBy=price&sortDir=asc
5
Express → allowlist check
sortBy and sortDir validated against hardcoded arrays before SQL interpolation — prevents ORDER BY injection
6
Express → SQLite (2 queries)
① SELECT COUNT(*) WHERE [conditions] → total   ② SELECT * WHERE [conditions] ORDER BY … LIMIT 50 OFFSET 0
7
SQLite → Express → SearchPage → UI
Table renders rows, "X records found" counter updates, Pagination strip appears
📄 Phase C — Pagination
8
🧑 clicks page N → SearchPage
handlePageChange(N) updates filter state and re-fires the same search query
9
Express → SQLite
Same filter conditions with OFFSET = (N-1) × pageSize — only that page's rows fetched
10
SQLite → UI
Table refreshes with page N rows. Pagination strip highlights new current page.
✏️ Phase D — Inline Edit
11
🧑 clicks ✏ Edit → PricingTable
setEditingId(row.id) — that row switches from read-only text to input fields (store, sku, name, price, date)
12
🧑 changes a field value
e.g. Updates Price from 9.99 to 11.49 in the price input
13
🧑 clicks ✓ Save → api/pricing
updatePricingRecord(id, editState) called — only the changed fields are sent in the request body
PUT /api/pricing/:id  { "price": 11.49 }
14
Express → express-validator
Validates: price ≥ 0, store_id length ≤ 100, record_date is ISO-8601, etc.
❌ Validation fails → HTTP 422 ValidationErrors → inline save-error message shown in row
✅ Validation passes → continue below
15
Express → SQLite
UPDATE pricing_records SET price = COALESCE(11.49, price), updated_at = now() WHERE id = :id
16
SQLite → Express → SearchPage → UI
HTTP 200 returns the full updated record. Record is replaced in local React state — no page reload. Row reverts to read view with new value ✅

REST API Reference

All endpoints on the Express server (port 4000)

Method Path Description Response
POST /api/pricing/upload Upload CSV — validates all rows, bulk-inserts atomically 201 { uploadId, rowsInserted, fileName }
GET /api/pricing List/filter records — 7 query params, paginated, sortable 200 { data: [], pagination: {} }
PUT /api/pricing/:id Partial update — send only the fields you want to change 200 { message, data: record }
GET /api/pricing/upload-logs Paginated upload audit history with status and row counts 200 { data: [], pagination: {} }
GET /health Server health check 200 { status: "ok", ts }
